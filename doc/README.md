# 课件目录说明

本目录是展厅接待、教学讲解和课堂生成资料的索引区，只保留本说明和 `manifest.json`。PPT、视频、图片等原件统一存放在 GitHub Release，不再提交到 `doc/`。

接待智能体先生成或修改接待流程前，必须先阅读本文件，再根据客户类型、关注点和已看内容选择合适课件。处理文件前，先运行下载器把 Release 原件下载到本机缓存：

```powershell
node agents/skills/nxn-resource-publisher/scripts/resource-download.mjs --catalog-url https://3fu.github.io/nxn_resource/catalog.json --output "<cache-dir>" --all --json
```

下载器的 JSON 结果会在 `resources[].path` 返回本机真实路径，并在 `id`、`type`、`title`、`originalName` 和 `sha256` 中返回对应元数据。生成 `video(...)`、`ppt(...)`、`file(...)` 时必须使用这些本机路径，不要再引用不存在的 `doc/<文件名>`。

GitHub Release 访问不稳定时，脚本会自动读取 `HTTPS_PROXY`、`ALL_PROXY` 和 `NO_PROXY`，并使用系统 `curl` 下载。也可以直接传 `--proxy "<proxy-url>"`、`--retries 5`、`--concurrency 1` 和 `--stall-timeout 120`；重跑时已校验文件会跳过，失败项可单独重试。

## 接待流程选课件规则

- 先看客户关注点，再选课件：公司实力用公司介绍，系统能力用 NXNOS，企业转型和合作模式用 AI 转型方案，工作站/合伙人用超算工作站，数字员工交付用实机演示类视频。
- 生成 `video(...)`、`ppt(...)`、`file(...)` 时，必须使用下载器返回的本机真实路径。
- PPT/PPTX 用 `ppt(...)`，视频用 `video(...)`，图片用 `file(...)`。
- 如果客户已经看过某个资料，除非用户明确要求重看，否则优先选择未看过且与关注点更匹配的资料。
- 如果本机缓存中没有资料，先重新运行下载器；不要凭记忆拼接路径或使用旧文件名。

## 维护要求

- 新增、删除或重命名课件后，必须同步更新本 README 和 `doc/manifest.json`。
- 接待流程引用课件前，先确认本 README、`doc/manifest.json` 和下载后的本机缓存一致。
- 不确定资料内容时，先向用户确认，不要编造课件说明。
- 本目录不再保存原件，同一批资料统一发布到资源仓库 `3Fu/nxn_resource` 的 GitHub Release；对外发布目录见该仓库 `docs/catalog.json`。
