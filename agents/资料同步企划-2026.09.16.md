## 二、现状核实（只读勘察结论）

### 2.1 资源仓库

- 远程 `https://github.com/3Fu/nxn_resource`（public），GitHub Pages 发布 `main/docs`。
- 仅跟踪 9 个文件：`docs/catalog.json`、2 份历史目录、4 个预览文件。
- 当前 `catalogVersion = 2026.09.10.1`，公开目录 9 项。
- 原件不在 git 中，全部通过 GitHub Release 分发。
- `agents/` 未纳入版本控制；仓库没有 `.gitignore`。

### 2.2 teacher\doc

- 素材 19 个 + `README.md`，合计 968,385,461 字节（约 923.5 MiB）。
- 构成：`mp4` × 11、`pptx` × 6、`png` × 1、`jpg` × 1。
- `README.md` 已描述 18 项，缺少 `无限画布使用教程v20260916.mp4` 的说明。
- `人工智能合资公司各智能体交付视频.mp4` 与 `拓客部门实机演示.mp4` 内容哈希相同。

### 2.3 两边差异

- 官网现有 9 项中只有 2 项与 `teacher\doc` 对应：`operations-training`、`ai-nxnos-training`。
- 以下 7 项在 `teacher\doc` 中不存在：`workstation-deck`、`poster-h106`、`poster-h106h2`、`application-form`、`workstation-description`、`application-checklist`、`application-template`。

### 2.4 技术约束

- GitHub 单文件 100 MiB 硬上限：`呆马公司介绍视频.mp4`（386.0 MiB）、`人工智能合资公司-v1-2026.6.16.mp4`（103.5 MiB）不能进 git；另有 2 项超过 50 MiB 建议上限。
- 按「只提交可提交部分」规则，`doc/` 实际入库 17 项、约 434 MiB；2 项大文件以清单加 Release 方式管理。
- 2 个视频为 HEVC 编码，浏览器兼容性有风险；`NXNOS功能模块介绍.mp4`（96.2 MiB）已超过预览 95 MiB 上限。
- 执行修订（原「11 个 MP4 转 H.264/AAC + faststart 并压到 95 MiB 内」的方案已作废）：视频不再转码。GitHub Release 直链支持 Range（实测返回 `206 Partial Content` + `Accept-Ranges: bytes`），可播放的视频直接在线流式播放并可拖动进度；浏览器不能播放的 HEVC 项以 `previewKind: download` 呈现“请下载观看”。PPT 预览仍为导出 PDF。
- 本机：`ffmpeg` / `ffprobe` 可用，PowerPoint 已安装，LibreOffice 缺失，资源仓库未安装 `jszip`。
- 原发布脚本会把全部原件读入内存打包 ZIP；现已在技能内改为流式 STORE ZIP，约 1 GB 素材规模下不需要整包入内存。

### 2.5 官网侧现状（改造输入）

- 工程为 Vite 项目，脚本：`dev` / `build` / `preview` / `lint` / `lint:fix`；依赖中已有 `jszip`。
- `src/services/resourceCatalog.js` 集中了加载地址、校验规则与加载函数，并转发内置快照。
- 内置快照 `src/data/workstationResourceCatalog.js` 当前停在 `catalogVersion = 2026.09.09.2`，落后线上目录 `2026.09.10.1` 一个版本。
- 加载地址写死三条：Pages 根、jsDelivr、raw。
- 校验硬编码了资源类型枚举、预览类型枚举、允许域名白名单与 15 个必填字段；`catalogVersion` 低于内置快照会被直接拒绝。
- 资源中心页面 `src/views/WorkstationResources.vue` 同时消费内置快照与加载函数。

## 三、官网兼容基线契约（重构后必须继续成立）

1. 三条目录地址必须继续有效：`https://3fu.github.io/nxn_resource/catalog.json`、`cdn.jsdelivr.net/gh/3Fu/nxn_resource@main/docs/catalog.json`、`raw.githubusercontent.com/3Fu/nxn_resource/main/docs/catalog.json`。
2. Pages 根对应仓库 `docs/`，`docs/catalog.json` 与 `docs/previews/**` 的路径与文件名契约保持不变。
3. `schemaVersion` 必须为 `1`；`resources` 为 1–500 项。
4. 每项必填字段：`id`、`type`、`typeLabel`、`title`、`description`、`format`、`size`、`url`、`downloadUrl`、`downloadName`、`downloadLabel`、`previewKind`、`sha256`、`assetKey`、`updatedAt`。
5. `id` 必须匹配 `^[a-z0-9][a-z0-9-]*$`；`sha256` 必须是小写 64 位十六进制。
6. 所有 URL 必须为 HTTPS 且落在允许域名内：`3fu.github.io`、`cdn.jsdelivr.net`、`raw.githubusercontent.com`、`github.com`、`objects.githubusercontent.com`、`release-assets.githubusercontent.com`、`ghproxy.net`、`gh-proxy.com`。
7. `catalogVersion` 必须不低于官网内置快照版本，因此新版本号必须大于 `2026.09.10.1`。
8. `bundle` 的 `assetKey`、`title`、`size`、`url` 必填，`url` 同样受域名白名单约束。

第 4、5、6、7 条中与枚举、快照下限相关的部分将在第 4 章被放宽，其余条款保持。

## 四、官网侧最小改造集（为更新便利而改）

目标是让“更新一次资源”不再需要手改官网源码，也不因为新增素材种类而卡住。

> 执行状态：第 1–4 条与新增第 6 条已实施，`npm run build` 通过（3355 个模块，约 1 分 44 秒）；第 5 条本轮未做（维持“可选”）。

1. **内置快照自动同步**（已实施）：新增 `scripts/sync-catalog-snapshot.mjs`，可由远端目录地址或 `--from <本地 catalog.json>` 重新生成 `src/data/workstationResourceCatalog.js`，并增加 npm 脚本 `sync:catalog`。
2. **取消快照作为版本下限**（已实施）：`validateCatalog(input, minimumVersion)` 不再默认套用内置快照版本，远端目录只按结构校验，快照仅承担“取不到远端时的降级展示”。
3. **放宽类型与预览枚举**（已实施）：`type`、`previewKind` 由硬编码集合改为格式约束 `^[a-z][a-z0-9-]{0,31}$`，已知类型精确渲染、未知类型走通用卡片。
4. **集中加载配置**（已实施）：三条加载地址与域名白名单收敛到新文件 `src/config/resourceCatalog.js`，`src/services/resourceCatalog.js` 只做校验与加载。
5. **可选：共享校验规则**（未做）：由资源仓库输出 JSON Schema，官网在构建期或运行期引用，避免两侧规则各自漂移。
6. **新增“请下载观看”预览分支**（已实施，为承接新策略而增）：`src/views/WorkstationResources.vue` 的预览区改为 `document` 分支 + 兜底分支，兜底渲染 `download-preview-pane`（下载按钮与换线提示），用于不能在线播放的素材。

明确不做：资源中心 UI 改版、路由与视觉调整、与本次兼容无关的重构。
